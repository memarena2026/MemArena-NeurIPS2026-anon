P1 — High-Value Text Improvements
============================================================================

P1-1. Add or tighten one main-text sentence explaining MASim realism limits.
  Reviews repeatedly ask whether synthetic conversations resemble real human
  dialogue. We already have an appendix exemplar and limitations. The main text
  should briefly say MASim is evaluation-aware and synthetic, not a claim of
  full ecological realism; appendix examples and corpus statistics support
  inspection.

P1-2. Make memory-probe density less suspicious.
  0428review2 explicitly notes that MASim memory probes may bias the corpus
  toward memory-heavy tasks. Discussion currently mentions dense memory-probe
  distribution. Strengthen this with one clear sentence: memory probes are part
  of the benchmark stress design, but system rankings may depend on this density.

P1-3. Surface D6 scenario composition more concretely.
  The reviewer asks for explicit-rule / autonomous / identity / contextual
  categories and DENY/ALLOW balance. Appendix seems to have a scenario-family
  breakdown; add a compact main-text pointer or one phrase in Section 5/7 so
  readers do not need to hunt through appendix.

P1-4. Add a short D6 example in main text only if space allows.
  The appendix examples are useful. A one-sentence example near the D6 scoring
  paragraph could reduce ambiguity around REFUSAL vs NONE vs COMPLY. Do not add
  a long protocol block; integrate it naturally.

P1-5. Related work: explicitly position against Chronos and SECOM if citations
  are available.
  0428review2 asks for temporally structured memory systems and segment-level
  memory management. We do not need to run them, but we should state that they
  are complementary architectures and that MEMARENA is an evaluation substrate
  stressing ego visibility, daily density, and permission semantics.

P1-6. Related work: keep MemoryBench / ATM-Bench / PersonaMem comparison tight.
  0428review asks for these recent benchmarks. The draft already cites several;
  ensure the comparison is not just name-dropping. One concise contrast is enough:
  they evaluate continual learning / personal memory / partial observability,
  while MEMARENA combines ego projection, coherent single-world dialogue, daily
  load, and permission-aware scoring.

P1-7. Broader Impact: add two missing risk angles if page budget allows.
  The current privacy paragraph is good. Add concise mentions of device theft or
  malicious local apps as local-memory risks, and the positive environmental /
  energy implication of smaller readers. Keep it short.

P1-8. Energy claim: keep the caveat attached to the headline.
  Main text already says GPU-only and CPU/DRAM/I/O excluded; do not let Abstract
  or Finding 3 read like end-to-end device energy. If needed, add "answer-time
  GPU energy" consistently and reserve "lifecycle energy" for the amortized
  calculation with K threshold.

P1-9. Amortization threshold: make low-query regimes explicit.
  Reviewers notice K≈5k queries/ego may be high for some assistants. Current
  text says below threshold it is a capability argument. Ensure Discussion or
  Finding 3 keeps this caveat visible.

P1-10. Clarify "Avg" in every place where readers may infer safety.
  Current Section 5 and Table 4 lead-in are good. Check Abstract, Intro, and

P1-11. D6 sample-size caveat.
  Discussion already says 200 items per seed and fine breakdowns exploratory.
  Verify that this caveat is near enough to the D6 claims, not only buried late.

P1-12. BGE-M3 / dense retrieval configuration details.
  Reviewers ask for exact dense-retrieval setup and whether hybrid lexical+dense
