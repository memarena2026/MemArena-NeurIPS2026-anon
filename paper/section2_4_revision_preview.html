Conversational Memory Benchmarks

Goal: make the paragraph state not only the topic, but the trajectory of prior benchmarks.

CurrentTopic stated

Recent memory benchmarks make different parts of the personal-memory problem measurable. LoCoMo and LongMemEval anchor the long-transcript line, alongside related transcript-centric suites such as BEAM, PersonaMem-v2, and MemGallery; these benchmarks make long-horizon recall, temporal QA, and retrieval failures concrete over extended dialogue histories.

EverMemBench moves toward richer persistent environments through multi-party collaborative dialogue, group-chat histories, evolving decisions, role-conditioned personas, and tasks for fine-grained recall, memory awareness, and profile understanding.

Taken together, these benchmarks show that personal-memory evaluation spans long-horizon recall, persistent social interaction, and continual adaptation. Privacy and Permission

Goal: move from a broad privacy topic to the concrete reason D6 belongs in the benchmark.

CurrentBenchmark requirement

A personal-memory benchmark should ask not only whether an assistant can recall a fact, but whether that fact should be disclosed to the current requester. Privacy work around LLMs and agents increasingly frames disclosure as contextual rather than binary, drawing on contextual integrity and testing whether models respect social roles, norms, and access boundaries.

We use this idea operationally: D6 evaluates requester-conditioned access decisions against explicit scenario permissions, so a personal memory assistant must decide both what it knows and what it is allowed to say.

ProposedFailure mode first

Design Principles Paragraph

Goal: clarify that the three principles are measurement constraints, not just labels.

CurrentPrinciples named

Three design principles make those dimensions measurable in the target personal-agent setting. Ego-centric projection means each user's observable history is restricted to conversations they actually participated in or witnessed.

Activity-density calibration means corpus scale is set to roughly 10K tokens/person/day with explicit day boundaries, so write pressure, recency, and temporal provenance are part of the workload. Simulator Paragraph

Goal: emphasize that world and assistant-facing memory stream are co-generated before questions are sampled.

CurrentRole stated

MASim's role is to create the social world and the assistant-facing memory stream together, before any evaluation question is sampled. Each simulated person is a persona-driven agent with RIASEC-typed personality, structured memory, and persistent social ties on a Dunbar-layered graph. A world event broadcaster routes events through a visibility matrix, creating controlled information asymmetry while preserving full provenance.

From this shared state, MASim generates two complementary dialogue streams. Person-person sessions build the social world through schedules, events, groups, locations, and remote contact. Person-agent sessions model the personal-assistant interface through activity narration, memory reflection, and memory probes. Thus person-person dialogue supplies socially distributed evidence, while person-agent dialogue supplies natural memory updates and memory queries. Both streams are finalized into the same provenance-tracked state before evaluation instances are built.

Full agent formalization, prompts, and scheduling are in Appendices; corpus distribution statistics and a representative dialogue exemplar are in Appendix.

Built-in Ground Truth and Ego-Centric Projection

Goal: tell readers the paragraph converts generated world state into labels and user-specific evidence.

CurrentMechanisms first

Ground truth derives from two mechanisms. Simulation-derived labels for D1, D2, D4, D5, and D6 are exact functions of the logs and require no annotation. LLM-generated labels for D3 are hardened via paraphrase rewriting, temporal rewrites, and counterfactual probes; where paraphrase hardening applies, we enforce Jaccard lower than 0.3 so that queries do not reuse near-verbatim corpus phrasing.

After generation, an ego-centric projection converts the shared world trace into each user's observable history. We also define an oracle-retrieval view that exposes only the annotated evidence sessions for each query, allowing us to separate retrieval failure from downstream reading and reasoning.

Temporal Isolation and Batching

Goal: frame temporal isolation as a synchronization choice, not as leakage or a human-memory claim.

CurrentRule framed as count

The simulator also needs a rule for how many near-simultaneous interactions can proceed before their newly created memories are synchronized. MASim therefore discretizes time into synchronization intervals: within one interval, person-person and person-agent sessions are generated from the same start-of-interval memory snapshot, and extracted facts, feelings, and metadata are committed together when the interval closes.

This is a modeling choice about when personal-agent activity streams synchronize, not a claim that human memory updates only at that granularity. We instantiate the interval as one simulated day because MEMARENA is calibrated to an activity-density target of roughly 10K tokens/person/day, and daily schedules provide an interpretable unit for routines, locations, encounters, and event visibility. Other synchronization intervals could be used for deployments requiring finer state propagation, but day-level intervals match our density target while preserving week-scale, multi-session dependencies. Engineering details and ablations are deferred to Appendix.
